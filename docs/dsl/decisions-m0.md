# M0 decisions

Choices made where design.md is silent. Append a row for every new one: topic | decision | reason.

| Topic | Decision | Reason |
| --- | --- | --- |
| Layering | All data definitions (Time, Target, Ref encodings, plan models, op argument models, catalogs, presets, the registry store and decorators) live in `eks_harness.ir`, which never imports `eks`; `eks` holds proxies, tracing, builders, planning and discovery and re-exports the public names. | Keeps the public surface of the design (`eks.Time`, `eks.by`, `@eks.op`, ...) while avoiding import cycles between the SDK and the IR the engine consumes. |
| Validator location | `eks_harness.engine.validator`, with `eks.validate` as the client wrapper. | The design places the validator in the engine; clients still validate locally because it does no IO. |
| Time JSON | A `Time` serializes to its canonical grammar string in typed fields (no `$time` wrapper). | Times are never runtime values, so a typed string field is unambiguous and readable. |
| Time offsets | Offsets are kept as separate bar, beat, frame and tick components, applied in that order: bar space, beat space, then frames and ticks. | Gives one canonical form, makes `+` commutative, and keeps `beat:8+1b` exact under tempo changes. |
| Tick unit | `tk` is a unit in the grammar. | Every value needs a canonical spelling; times finer than 10 microseconds cannot be written in seconds. |
| Indexing | `beat:N`, `downbeat:N`, `bar:N`, `marker:x#N` and word occurrences are 0-based. | Matches the design's `bar:0` and `beats("downbeat")[0:8]` and Python slicing. |
| Words in times | `word:[source:]'text'[#n]` and `word:[source:]#i`. | Covers several transcripts and repeated words with one grammar. |
| Clip-local time | In clips, layers and scene animations, unanchored times and `start`/`end` are local; musical, cue, marker, word and `f:N` anchors are absolute. | Fixes the old segment-local versus absolute bug with a rule that reads naturally (`fx.zoom` spans the clip, `beat:8` is the song's beat). |
| Strict time params | Builders accept `Time` instances only; strings and numbers raise `TypeError`. `--set` and JSON parse strings. | "One grammar everywhere" and no ambiguity with target strings. |
| Target JSON | `{"by": kind, "args": {...}, "within", "near", "nth"}`; `.last` is `nth: -1`. | One generic envelope keeps plugin target kinds possible without rebuilding unions. |
| Target shorthand | `#id` is a test id, `prefix=rest` picks a kind, every other string is exact text; no CSS guessing. | Deterministic parsing; the old driver's CSS heuristics are exactly the ambiguity the strict model removes. |
| Node ids | `n` + 10 Crockford base32 characters of SHA-256 over scope path, the call chain (file, qualname and the hash of the call expression's source text per user frame), the op and an occurrence counter. Seed resources use their resource path instead. | Stable under blank lines, comments and unrelated edits; identical for identical source. |
| Resource ids | `r` + 7 base32 characters of the hash of kind and identity. | Stable and content-derived instead of `r1`, `r2`. |
| Hash coverage | Node hashes cover op, op version, executor version, args with refs replaced by hashes, uses, after, out, pin, branches and the clock the node depends on (see "Clock in node hashes"); plan hashes exclude name, tags and source; `src` is never hashed. | Renames and line moves do not invalidate caches; changing an argument changes its lane after it. |
| Arg dumps | Node args are `model_dump(mode="json", by_alias=True, exclude_none=True)`; optional fields default to `None` and non-`None` defaults are not nullable. | Explicit defaults make hashes follow default changes; excluding `None` keeps plans readable without losing meaning. |
| Control flow encoding | `when`, `each`, `parallel`, macros, recordings, cassettes and takes are container nodes with named `branches`; `otherwise` is the `else` branch of the preceding `when`. | Sub-plans stay nested for the journal, the debugger and diffs, and refs into bodies get clear visibility rules. |
| Literal `eks.each` | The body is traced once as a template and copied per element at plan time, ids suffixed `.i`. | A `with` body runs once in Python; templates keep the design's plan-time expansion exact. |
| Ordering | Effectful ops chain in program order (per lane inside `eks.parallel`); pure ops and seed resources depend only on what they reference. | Matches "nodes on the same lane run in program order; independent lanes in parallel". |
| `@eks.op` | Decorates the argument model class; the executor is a `"module:qualname"` reference resolved by the engine; calls go through `s.call(Model(...))` or `s.op(name, **args)`. | Keeps authoring import-light and fully typed through the model constructor. |
| Extensible kinds | Effects, transitions, easings, curves, overlays and marker sources use `Annotated[SerializeAsAny[Base], Poly(category)]`, dispatched through the registry on `kind`. | No fragile runtime rebuilding of pydantic unions when plugins register kinds. |
| Pyright and kinds | Polymorphic bases are declared with class keywords `frozen=True, extra="forbid"` and subclasses repeat `frozen=True`. | Pyright accepts `Literal` narrowing of `kind` only on frozen dataclass-transform models. |
| Easing names | `linear`, `in_quad`, `out_quad`, `in_out_quad`, `in_cubic`, `out_cubic`, `in_out_cubic`, `out_bounce`, `out_elastic`, `out_back`, `cubic_bezier`; old names are accepted by `eks.ease`. | The design writes `ease="out_cubic"`. |
| Colors | Hex strings `#rrggbb[aa]` everywhere in the new IR. | Matches overlay styles and CSS; replaces RGBA tuples. |
| Plugin catalog types | `PluginEasing` and `PluginTransition` are dropped. | Plugins register their own models through `@eks.easing` and `@eks.transition`. |
| Beat flash default | `beat_flash` and `beat_glitch` default to the `beat` stream. | `beat` is the clock grid every song analysis provides. |
| Root seed naming | On `@eks.flow` and `sc.take`, `seed` is the scenario and `root_seed` the random seed; elsewhere `seed` is the random seed. | The design uses both meanings; types (str versus int) keep them apart. |
| `platform` parameter | `platform` is a reserved keyword of `eks.plan` for flows; flows may not declare it. | `eks.plan(fn, **params)` needs a way to pick the platform of a matrix flow. |
| Platform resolution | The flow's own platforms, else the app profile's (`<app>/.harness/app.toml`), else the caller must pass one. | The design's `subeler` example names an app but no platform. |
| Personas | Persona resources are seed resource kinds flagged `persona=True`; the plan lists their keys in `Plan.personas`; flows are checked against the seed named in their session. | "Personas come out of the seed graph." |
| Scene clocks | A standalone scene has an external tempo (`TempoMap(external=True)`) unless it declares `bpm`; musical times resolve on the embedding score's clock. | The phone scene of the design uses `bar:` times without a song of its own. |
| Embedded scenes | `sc.scene(fn, **inputs)` runs the scene function inside the score's trace and records its render node there. | One plan per score with Merkle-hashed scene inputs (the take ref). |
| Take body | `sc.take(...)` records the `score.take` container immediately; `take.flow()` fills its body once. | The design binds `take` before `with take.flow()`. |
| Media inputs | Media strings become `media.source` nodes; relative paths are relative to `Plan.base`, the entry file's directory. | Every media input gets one probe and fingerprint node the render nodes reference. |
| Pace presets | One built-in pace preset, `demo`, with today's demo values; takes run without pacing. | "The four pace definitions go (one pace preset remains)". |
| Network presets | `wifi`, `4g`, `3g` (Chrome Fast 3G), `slow-3g` (Chrome Slow 3G), `offline`. | Deterministic named profiles for `s.net.shape`. |
| Viewport presets | `desktop` 1920x1080, `phone` 390x844 at 3x, `tablet` 820x1180 at 2x. | The design writes `viewport="phone"`. |
| Overlay renderers | Every overlay kind renders on video; screenshots do not render `title`; `blur` renders live on web only. | Carries over the old annotate limits and the React Native overlay's capabilities. |
| Review check naming | The media template match check is named `template` (the old review kind `visual`). | `visual` now names the golden screenshot diff of checkpoints. |
| Network patch | `.patch(lambda_path=..., value=...)` keeps the design's keyword and stores it as `path`. | The design shows `lambda_path`. |
| Fake media | `s.fake.arm(media=)` takes a media ref; app fixture files go through `fixture=`. | Keeps the environment builders independent of the media builders. |
| API ops | `api.get`, `api.post`, `api.put`, `api.patch`, `api.delete`, args field `path`. | The design's IR example uses `"op": "api.get"` with `"path"`. |
| Module names | `eks.editing`, `eks.scoring`, `eks.assertions`, `eks.effects` instead of names equal to exported objects. | A submodule named like an exported decorator or object (`edit`, `score`, `expect`, `fx`) shadows it on first import. |
| Python floor | `requires-python >= 3.13`; `uv.lock` relocked. | Design decision; the relock only drops 3.12 markers. |
| Lint baseline | New code is clean under ruff 0.16's default rule set (no repo config). | The instruction requires ruff-clean code and the repo has no narrower config. |
| Stubs | `py.typed` and inline annotations; no generated stub files. | Plugin ops are typed by their models through `s.call`, so stubs add nothing. |
| CLI exit codes | `plan`: 0 valid, 1 invalid, 2 build or usage errors; `ops` unknown op: 6. | Reuses the CLI's existing exit code table. |
| Seed resource ids | `data.create` nodes use the resource path as `id_key`. | Seeds are graphs; ids should follow the resource, not the line that declared it. |
| Test isolation | The `eks_registry` autouse fixture lives in `tests/conftest.py` and only acts on tests under `tests/eks`; `tests/eks` has no `__init__.py` and no `conftest.py`. | A package `tests/eks` would shadow `src/eks`, and a second `conftest` module breaks the existing `from conftest import ...` imports under pytest's prepend mode. |
| Scene references | `sc.scene(...)` and `sc.gfx(...)` accept a scene function or the name of a registered scene; `plan_spec` loads the tree's seeds and scenes before planning. | Files under `.harness/` are not a Python package, so a score refers to scenes by name instead of importing them. |
| Re-loading entry files | `eks.discovery.load_file` re-executes a file when its content changed or its entries left the registry. | Keeps the CLI fast and keeps tests independent when the registry is restored between them. |
| Workspace module | `plan_spec` and `seed_personas` live in `eks.workspace` (wave 3, with the validator) instead of `eks.discovery`. | They need tracing and discovery together; keeping them out of the wave-2 discovery module lets each package test what it owns. |
| Target kinds mapping | `parse_target`, `ensure_target`, `validate_args` and `check_target` merge the `kinds` argument over `BUILTIN_KINDS`, so built-in kinds and prefixes are always known. | The grammar always accepts the built-in prefixes, and a caller passing only plugin kinds should not lose `#id` or `role=`. |
| Plugin shorthand | `prefix=rest` for a plugin kind puts `rest` into the first declared field of its args model; a kind whose model has no fields has no usable shorthand (`TargetError`). | The built-in kinds follow the same rule (`id`, `text`, `selector`, `kind`, `name`); role, point and rect keep their own syntax. |
| Malformed shorthand | An empty rest (`text=`, `css=`), an empty role or an empty name after `role=ROLE:`, and point or rect parts that are not plain decimal numbers (`nan`, `inf`, `1_0`) raise `TargetError`; whitespace around numbers is allowed. | Keeps every prefixed form explicit and JSON-safe; a bare string still never raises. |
| Target modifiers | `within`/`near` replace an existing scope or anchor; their string forms parse with the built-in kinds only. | `model_copy` semantics; `eks_harness.ir.target` cannot see the registry, and plugin targets are passed as `by.custom(...)`. |
| Target builder values | `by.*` text arguments keep `str`, `$fmt`/`$ref`/`$item` models and dicts, and turn anything else into `str(value)`; `by.custom` dumps models, keeps JSON values and turns other values into `str(value)`. | Refs become sentinels inside a trace without importing `eks`; plugin args stay JSON. |
| `describe` | Uses a shorthand only when it parses back to the same target with the built-in kinds, else `by=<kind> <args as sorted JSON>`; nested targets that carry modifiers are parenthesized; plugin kinds always use the `by=` form. | Descriptions never mislead (for example `text=#1`, `exact=False` text) and stay unambiguous for nested scopes. |
| Target errors | Invalid args from `by.*`, `parse_target` and `validate_args` raise `TargetError` (a `ValueError`) wrapping pydantic's messages; `check_target` with an unknown surface returns one problem naming the surfaces. | One exception type for authors, still converted by pydantic validators. |
| Target args are finite and aliased | Builtin target args models set `allow_inf_nan=False`; `by.custom` values and every validated args dump (plugin models included) must hold only finite numbers or raise `TargetError`; args are stored with `by_alias=True`. | Keeps plan JSON canonical and hashable, and makes `validate_args` idempotent for plugin models that alias fields. |
| `$fmt` literal parts | When `map_exprs` replaces a `$fmt` part by a literal, strings are inserted verbatim and other JSON values as compact JSON text (`7`, `1.5`, `true`, `null`, `{"a":1}`); a `$fmt` returned for a part is spliced in. | One rendering for the hub and the TS workers; matches Python for strings and numbers, the common cases. |
| Ref type compatibility of lists | `compatible("list[A]", "list[B]")` is `compatible(A, B)`. | The element-wise reading of the scalar table; `list[int]` into `list[float]` is safe and `list[json]` is checked at run time like `json`. |
| Ref types of model fields | `infer_path` reads `Artifact`/`MediaInfo` fields: `Time` fields are `str`, string `Literal`s are `str`, `fps` (int or `"30000/1001"`) is `json`. | Matches the JSON the executors return for these models. |
| Path step strictness | `RefExpr`/`ItemExpr` reject boolean path steps; `find`/`filter` compare with JSON equality (`true` never equals `1`) and raise when their values still hold refs. | Pydantic would coerce `true` to index 1, and Python's `True == 1` would match the wrong elements. |
| Hashing details | `$item` depth is an integer; each containers are the `ctl.each` nodes; `plan_hash` reads the stored node hashes (`PlanError` when missing) and hashes `outputs` with refs replaced by node hashes; `hash_plan(executor_versions=)` overrides per op and falls back to the registry. | Keeps `plan_hash` cheap and consistent with the node hashes `hash_plan` filled. |
| Canonical JSON errors | Non-finite floats raise `ValueError`, every other non-JSON value (tuples, non-string keys, sets, bytes) raises `TypeError`; `resource_id` rejects a `kind` key in the identity. | `allow_nan=False` semantics; a tuple or an int key would otherwise serialize silently. |
| Sentinel tokens | `SentinelTable.token(ref)` returns `r<n>` (identity map, numbered from 0 per table) and `lookup` takes the same; `Ref.__format__` wraps it in the sentinel characters. | Matches `SENTINEL_PATTERN`'s group. |
| `ref_kind_of` inputs | Also accepts a pydantic `FieldInfo` (its metadata first) and PEP 695 / `TypeAliasType` aliases. | Pydantic strips `Annotated` into `FieldInfo.metadata`, which is what the validator walks. |
| Target scalar strictness | `Target.nth` and the builtin `exact` flags and point/rect coordinates are pydantic `strict=True` fields (strict float still takes ints); `validate_args` compares args by sorted JSON text, so type-only coercions (1 to 1.0) are stored. | Hand-written plan JSON is rejected instead of silently coerced (`nth: true`, `exact: "yes"`), and JSON-authored and builder-authored targets hash identically. |
| Time python dump | `Time` carries a `__pydantic_serializer__` ClassVar with the same plain serializer as its field schema: python mode returns the `Time` object, JSON mode the canonical string, also inside `Any`, `dict` and `Json` fields. | Without it pydantic turns the dataclass into a dict in python mode, which breaks contract 2.7, and untyped fields could not carry times into JSON. |
| Time construction | `Time(...)` normalizes int components to `Fraction` and raises `TimeError` for non-terminating `bars`/`beats`/`frames`, a non-terminating anchor index or fractional `ticks`. | Keeps the 2.2 invariant for direct construction too, so every `Time` can be formatted. |
| Tick spelling | Seconds, milliseconds and ticks share one `ticks` component, so `0.25s+1tk` canonicalizes to `176400001tk`. | The canonical form writes one tick token; round trip still holds. |
| TimeSet offsets | A `TimeSet` offset must be a duration: `TimeSet + anchored time` and resolving a set whose offset carries an anchor raise `TimeError`. The offset is applied to each point with resolution steps 2 to 5. | A second anchor has no meaning for a set of points; `beats[0:8] + t('1b')` stays exact under tempo changes. |
| Stream slice bounds | Stream slices never extrapolate: they stop at the end of the grid and drop points at or after the clock's `end` before the offset is applied; `downbeat` uses the bar starts when the clock has no downbeat grid. | Matches "until the grid or end runs out" and the half-open window rule. |
| Static grid length | `TimeContext.static` builds the beat grid up to the first point at or past the horizon and at least two full bars past the last tempo or meter change. | Extrapolation past the grid and the downbeat grid then use the final tempo and meter exactly. |
| Non-time inputs | `coerce_time` and `t.parse` raise `TimeError` (a `ValueError`) for anything but `Time` or `str`; `t(...)` raises `TypeError` for non-strings with the "bare numbers are not times" hint. | `coerce_time` serves JSON and `--set` paths where pydantic needs `ValueError`; `t()` is an authoring call like the builders. |
| Word folding | Words match on `fold_ascii(text).casefold()`, falling back to `text.casefold()` when folding leaves nothing (non-Latin scripts). | `fold_ascii` drops non-ASCII letters, which would make every Cyrillic or Arabic word match every other. |
| Negative bar math | `bar_start_beat` and `bar_index_at_beat` extrapolate with bar 0's meter for negative values; `beat_time` then rejects the negative beat. | Keeps the two functions inverse everywhere; the error surfaces where the contract puts it. |
| Word index form | `t.word(index=i)` rejects a non-zero `nth`. | `nth` counts text matches; an index already names one word. |
| Fps python dump | `Fps` fields dump as pydantic's default for `Fraction` (a string) in python mode and as `30` or `"30000/1001"` in JSON mode; attribute access gives a `Fraction`. | pydantic-core always stringifies `Fraction` in python mode; the IR uses JSON mode. |
| word text folding (P1) | `TURKISH_FOLD` translate, `casefold`, NFKD, drop combining marks only; no ASCII encode | `fold_ascii` drops every non-Latin letter, so Cyrillic or Greek words collided ('дом1' matched 'кот1'); diacritic-insensitive Turkish matching is kept |
| TimeSet shape (P1) | model validator: stream must match the name grammar and carry no `times`; explicit lists keep start/stop/step at defaults; start/stop/step are strict ints | contract 2.7 invariant now fails at plan validation instead of execution, and bools no longer pass as indices |
| Default target kinds (supersedes the string-form half of "Target modifiers" and the plugin half of "`describe`") | `kinds=None` in `eks_harness.ir.target` means `BUILTIN_KINDS` merged with a provider set by `use_default_kinds`; `eks.target` installs `REGISTRY.target_kinds` at import. `within`/`near`/`by.parse` also take `kinds=`; `describe` emits plugin shorthands when they parse back to the same target. Shorthands must fullmatch `[A-Za-z][A-Za-z0-9_.-]*` and be unique across distinct kinds, else parsing raises `TargetError` (`describe` falls back to `by=`). Test ids may contain ref sentinels (U+E000 `r<n>` U+E001). | The same string must mean the same target wherever it is written, without `ir.target` importing the registry; a shadowed or unreachable shorthand and `f"#row-{ref}"` turning into text were silent bugs. |
| Sentinel token numbering (P3, supersedes the "numbered from 0 per table" part of "Sentinel tokens") | `r<n>` numbers come from one process-wide `itertools.count` shared by every `SentinelTable`; each table maps its own numbers to refs and `lookup` raises for a number it does not hold. | Per-table numbering let a string formatted under one trace resolve silently to an unrelated ref of another trace that had already formatted refs. |
| Path step and scalar alias strictness (P3, extends "Path step strictness") | `PathStep` is `StrictStr \| StrictInt \| ...`, slice bounds are `StrictInt \| None`, and `RStr`/`RInt`/`RFloat`/`RBool` use `StrictStr`/`StrictInt`/`StrictFloat`/`StrictBool` (strict float still takes ints); the separate boolean-step validator is gone. | Lax mode turned `true`, `"1"` and `1.0` into index 1 and `"5"`, `"yes"`, `1` into op args, so loaded JSON stored values the builder never would and hashed differently; matches "Target scalar strictness". |
| Python regex anchoring (P3) | Validation regexes in `ir.types` and `eks.ref` use `fullmatch`; the shared `COLOR_PATTERN` keeps its `^...$` form for JSON Schema. | Python's `$` matches before a trailing newline, so `'#aabbcc\n'` and `'resource:tenant\n'` passed while the schema's own pattern rejects them. |
| Anchor shape (P1) | `Anchor.__post_init__` validates and normalises every anchor and raises `TimeError`: start/end take no fields; frame takes a whole index >= 0; beat/downbeat/bar take a terminating index >= 0; cue takes a name; marker takes a name and `nth` (None becomes 0); word takes exactly one of text (`nth` None becomes 0) or a whole index >= 0 (no `nth`), plus an optional source name; any field outside its kind is refused; indices become `Fraction`. `Time.anchor` must be an `Anchor`. | Anchor is public and Time objects pass through pydantic fields unchanged, so a hand-built anchor could format to text that does not parse back, or compare and hash unequal to its parsed twin; contract 2.4's round trip now holds for every constructible Time. |
| Tempo bounds (P1) | `TempoMap.bpm` and `TempoChange.bpm` are `Field(gt=0, le=MAX_BPM, allow_inf_nan=False)` with `MAX_BPM = 2000` exported from `eks_harness.ir.time`; `_beat_ticks` also raises `TimeError` for a non-finite or out-of-range bpm (for `model_construct` data). | `inf` raised a bare `ValueError` from `Fraction(repr(inf))` and a huge finite bpm made the static beat grid loop practically forever; 2000 bpm is far above any real music and keeps a 600 s grid at 20k points. |
| TimeSet offset and tempo strictness | `TimeSet` model validation rejects an anchored `offset` (ValueError, same wording as `TimeSet + time`); `Meter`, `TempoChange`, `MeterChange` and `TempoMap` numeric fields are `strict=True` (bpm stays `float`, which still takes ints but not bools or strings) | a JSON plan with an anchored offset or a `true`/`"120"` bpm must fail plan validation instead of at execution or as a silent 1 bpm clock, matching decision 87 for TimeSet slices |
| IR expression and plan models accept aliases only | `_Expr` (refs.py) and `_IR` (plan.py) drop `validate_by_name`; a shared `reject_field_name_keys` before-validator rejects python field names (`ref`, `item`, `fmt`, `filter_`, `slice_`, `len_`, `schema_`) with "unknown key"; refs built into mapping keys, path keys or find/filter field names raise RefUsageError | raw-JSON tooling (walk_exprs, referenced_nodes, node_hash) only knows the `$`-keyed forms, so by-name dicts were invisible refs; pydantic 2.14's JSON fast path silently drops by-name keys even with extra="forbid" (`{"len_": false}` became a len step) unless a before validator runs; a sentinel leaked into a key loses the dependency and puts a process-dependent token into plan JSON |
| Registry definition identity (P5) | A duplicate key replaces the entry when the object is the same or its `module:qualname` is; modules imported through a plugin `ImportScope` (`_eks_harness_plugin_<slug>_<hash>.`) compare as `<plugin id>/<module tail>`, so a changed plugin imported under a new scope generation counts as a reload; presets carry `PresetSpec.source` (`module:qualname` of the preset function) for this check. | Reloads and long-running hosts must not fail on their own definitions, while two different definitions of one key still fail naming both. |
| Reserved families (P5) | Every non-`eks` provenance (plugins and project code) is refused in the built-in families of 8.1, and a macro namespace may not be a built-in family (it would shadow `s.ui` and friends). | Built-in families describe the harness surface; a project op `ui.swipe` would read as built-in in the catalog and the schema. |
| Registry naming and shape checks (P5) | Resource kinds and parents, catalog and check kinds, preset categories and op branch names match `^[a-z][a-z0-9_]*$`; macro names are public identifiers; preset names match `^[A-Za-z0-9][A-Za-z0-9_.-]*$`; renderer media kinds, backend and policy names match `^[a-z][a-z0-9_.-]*$`; op `out` must parse as a ref type; platforms are a non-empty subset of web/ios/android; `branches`/`exports_body` need `container`; catalog models (not targets) must declare the registered `kind`; target shorthands match the shorthand grammar and are unique across kinds; overlay renderer slots are live/screenshot/video; resource `positional` names are model fields and persona kinds are keyed; a `PresetModel` registers only under its own category. | Every rule fails at registration with the offending name instead of later in the validator, the schema or the CLI. |
| Lookup errors (P5) | Unknown names raise `RegistryError` with up to three `difflib` suggestions (`did you mean 'ui.tap'?`), else the first 20 known names, else "none are registered"; `versions()` is sorted by plugin. | Matches 8.1 and keeps messages bounded. |
| Entry function shape (P5) | Entries are plain synchronous functions whose first parameter is positional; `*args`, `**kwargs`, positional-only parameters after the first, async and generator functions are refused; options are validated (tags without whitespace or commas and unique, `now` ISO 8601 with offset normalized like `Clock.now`, flow `timeout` a positive wall-clock duration, durations positive and unanchored, sizes positive, meter note values powers of two, preset, seed and backend names by their patterns) and option errors are `RegistryError`s starting with `@eks.<kind>:`. | Parameters are passed by name from the signature (`coerce_params`), and tracing calls the function once. |
| Entry file loading (P5) | `load_file` compiles the bytes it hashed (no bytecode cache read or written), drops the module's previous entries before executing it again (`Registry.drop_entries(module)`), checks cached entries by identity against the registry, and lets exceptions raised by the file propagate unchanged (the module is removed from `sys.modules`). | A same-size rewrite within one second replayed stale `.pyc` code; renamed entries must not linger; the traceback of a broken flow should point at the flow. |
| Discovery walk (P5) | `discover` and `find_app` skip every hidden directory (also `.claude/worktrees` copies) besides `node_modules`, `.git`, `.venv` and `__pycache__`, and ignore `_`-prefixed files; root files come first in folder order, app flows follow sorted by path. | Worktree copies would duplicate every app flow; `_helpers.py` modules are imports, not entries. |
| Plugin module loading (P5) | `load_plugins` imports each module once and imports it again (`importlib.reload`) when the registry lost anything it registered; any exception during the import becomes a `DiscoveryError` naming the plugin, its root and the module. `[plugin] modules` is a list of unique dotted module names and `Manifest.summary()` lists them. | Same semantics as `load_file` for restored registries; one error type for broken plugins. |
| App lookup (P5) | `find_app` prefers an `[app] name` match over a directory name match, raises `DiscoveryError` when two apps match at the same level, skips unreadable profiles of other apps and returns `AppInfo(profile.name, profile.root, profile.platforms)`. | Deterministic answers in monorepos with similarly named apps. |
| Call text normalization (P4) | The call expression hashed into a node id segment is its token stream (Python `tokenize`, comments and line breaks dropped) joined by single spaces (`eks.tracing.normalize_call_text`); `linecache.checkcache` runs before each read. | Collapsing whitespace runs still told `f( x)` from `f(x)` and kept comments inside multi-line calls; tokens make ids independent of formatting, and checkcache picks up edited files reloaded in the same process. |
| Transparent frames (P4) | `contextlib` frames count as library frames for call chains. | Every `with eks.when/each/parallel(...)` runs through `contextlib`; counting those frames would put stdlib paths into ids. |
