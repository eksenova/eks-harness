# M1 decisions

Choices made where design.md and contracts-m0.md are silent, for the engine and hub milestone. Rows are topic | decision |
reason. contracts-m1.md is the normative contract; these rows record why. Work packages report new rows in their results
and the integration step appends them here (contracts-m1.md section 24).

| Topic | Decision | Reason |
| --- | --- | --- |
| Concurrency model | The engine runs on threads: one thread per active run, a bounded worker pool per run for node bodies, synchronous executors. Async code is limited to route handlers and the event stream. | The platform's database connections are per thread, leases, backends and node jobs are thread based, and synchronous executors are the simplest contract for plugin authors. |
| Executor versions | Node hashes keep `OpSpec.executor_version` as authored (empty for built-ins); the executors registry's version, the executor's runtime version, the harness source digest for built-in executors and the fonts digest for text-rendering executors enter cache keys only. | Clients build and hash plans; folding hub-side executor versions into node hashes would make the hub's `plan.hash` check reject plans from any other client build, while cache keys are exactly where BL-003 asks for them. |
| Harness digest | Built-in executors are keyed by `_version.build_info()["sourceHash"]`, computed once per process. | A renderer or engine change without a manual version bump must not serve stale results; the source hash is already computed for updates and changes with every code change. Conservative invalidation beats a stale cache. |
| Instance keys | A node instance is `(node id, instance)` where the instance lists the enclosing each iterations (`each#k`) and dynamic sub-plans (`dynamic id`) joined by `/`; refs resolve to the longest prefix holding the producer. | Plan node ids are unique, so prefix lookup is unambiguous, and the same scheme serves runtime each, dynamic sub-plans, the journal and the debugger. |
| Each iterations | Runtime `ctl.each` iterations run one after another. | Literal each copies chain copy i after copy i-1 (contracts-m0 6), and a runtime each must mean the same thing; parallel work is what `eks.parallel` is for. |
| Untaken branches | Nodes of a `ctl.when` branch that is not taken are journaled as `skipped`. | The journal and the report then show the whole plan, and the debugger and the UI can tell "not taken" from "never reached". |
| Macro output | A `ctl.macro` node's run-time value is its resolved `params` object. | The macro's Python return value is returned to the author directly at plan time; the container value is otherwise unobservable, and its params are the one thing worth journaling. |
| Lease mutex | At most one leaf instance per lease resource runs at a time; containers hold the lease only during enter and exit. | A device or browser profile does one action at a time; program order already serializes lanes, and the mutex covers graph-ordered or ad-hoc nodes that touch the same lease. |
| Retries | Only idempotent ops retry automatically, only on failures their executor marks retryable, up to `engine.retries` times with a fixed backoff. | design.md 5.2 ("retries only where an op declares itself idempotent"); pure ops are re-run by the cache on the next run instead. |
| Soft failures | A soft failure ends the instance `soft_failed`; raised soft failures leave no output, returned ones keep their value. | Fail by default (design 2) needs a third state that never fails the run but still shows in the report. |
| Fail fast | The first hard failure that does not pause cancels every other running instance and marks pending ones `cancelled`. | Independent lanes are part of one flow; continuing after a failure would produce evidence of a state the author did not intend. |
| Debugging opt-in | Breakpoints, stepping and pause on error pause a run only when the run was started with `debug`, breakpoints or `break_on_error`; otherwise `debug.break` nodes pass and are journaled. | A source breakpoint left in a flow must not hang CI until the pause timeout; the CLI turns debugging on as soon as any break flag is given. |
| Breakpoint grammar | `node:ID`, a bare id, `op:GLOB`, `label:TEXT` and `when:EXPR` joined by commas, every criterion must hold, `when:` last. | Covers design 9's node id, op, label and condition in one string the CLI, MCP and UI share. |
| Condition language | A whitelisted Python expression subset over `node, op, label, src, attempt, instance, args, values, error` with a few string functions, evaluated by a tree walker, never `eval`. | The same safety stance as lambda curves (decisions-m0): no names, attributes or calls outside the list can execute. |
| Ad-hoc ops | The debugger's `do` action journals the op under node id `adhoc:<n>` at the root instance. | Design 9 lets a paused run take an ad-hoc op; journaling it keeps the run's history complete without inventing plan nodes. |
| Persona auth | `api.*` gets persona headers from registered providers, then a static `persona_headers` hook on the `@eks.backend` class, then the backend info credentials (`headers`, `token`, `username`/`password`, `api_key`). | The eksenova login is phase 2 work; M1 needs a real, testable seam that today's backend info already feeds, without inventing a new decorator. |
| Worker ops in M1 | Worker-located ops go through one real worker executor that calls the lease's `DriverPort`; M1 ships only the fake port, M2 adds real ports. | The engine side of typed op RPC is fixed now and M2 only plugs ports in; fakes simulate devices at the port, where M2's real work happens. |
| Fake profile | Fakes are opt-in per run (`fakes` in the request), cover only ops without a real executor unless forced, mark the run and every faked instance `simulated`, and list the faked ops in the report environment. | A hub must never report a fake success as real; making simulation explicit keeps "fakes for tests" useful for agents dry-running plans too. |
| Missing executors | Admission refuses a plan with an op no real executor or fake covers, naming the milestone that brings it. | A partial run that stops at the first unsupported op wastes devices and backends; refusing up front is honest. |
| Cache scope | Only pure ops are cached; a machine-dependent node whose executor has no resolver is executed but never stored or served. | BL-001: never key such a node by node hash alone; bypassing is always correct. |
| Resolvers | Machine-dependent executors predict their resolution before running (resolver), the key includes it, and the executor must report the same resolution afterwards. | The key must exist before execution to look the cache up; a mismatch means the prediction lied and the result cannot be filed under that key. |
| Content of inputs | `media.source` inputs are keyed by the content of the URI they name, resolved by the engine, independently of the media.source executor. | BL-002: artifacts mutate in place, and the content check works the same with fake and real media executors. |
| Cache blobs | Cached artifact outputs keep a copy (hard link when possible) in a content-addressed store and are re-ingested into the current session when the original artifact was deleted or changed. | Retention and in-place re-renders would otherwise turn a cache hit into a dangling or wrong artifact. |
| Plugin digests | Cache keys include the content digest of every plugin that contributes to the node or its pure inputs and a tree code digest for project contributions; hub registries are rebuilt when a digest changes. | BL-004: same plugin id and version with other code must not share results across machines or over time. |
| Isolated tree registries | The hub plans and runs against tree registries rebased on the built-ins only (`isolated=True`), pruned of inactive plugins and removed files, in bounded caches; the CLI and SDK keep today's registries. | BL-007; changing the default would break the M0 contract that a tree registry includes what was registered outside trees, which tests and `eks.plan` rely on. |
| Inline sources | Inline source is written to `<tree>/.harness/<folder>/_eks_inline_<hash>.py`, planned in the tree and deleted at once. | Planned as if it were a file of the tree, relative media and plugin owner addressing work unchanged; the `_` prefix keeps discovery from loading it and deleting it leaves the repository clean. |
| Path-based planning access | Planning from a tree path, a spec or inline source runs that tree's code on the hub, so it needs admin, or the matching access on the tree's own project; inline source needs admin. | Hub-side planning is code execution; tying it to the tree's project grants keeps members inside what they can already change. |
| Run ownership | A run belongs to a project and a session like artifacts and leases; leases it takes are owned by the instance `run:<id>` and claimed for the run. | Runs outlive the client that started them, and lease staleness and reuse rules must not hand a run's device to the caller's other work. |
| Backend leases of runs | A run always takes its own backend lease, also when the request names an existing `bl_` lease, which only selects the instance. | Releasing a run must not release a lease the caller still holds, and the backend stays up while either holds it. |
| Backend choice order | Request, plan definition, app profile `[backend]`, `@eks.backend_policy`, legacy policy contributions, project `[backends] default`. | Mirrors today's flow runner and backend policies while recording which source decided (BL-005). |
| Seed restores | A seeded backend needs a seed hook (M3) unless the run says `seed=skip`; fake profiles bring a fake hook. | Running a flow that names a seed against an unseeded local backend silently would make results meaningless; staging runs opt out explicitly. |
| Render slots | Engine render slots use the existing render queue through a thread-safe `claim`/`drop` API. | Legacy renders and engine renders share one concurrency limit and one queue view; the old context manager mutates `os.environ`, which breaks with several engine threads. |
| Sandbox isolation | The dynamic sandbox is a `python -P -s -B -m` child with `PYTHONHASHSEED=0`, rlimits, an audit hook that refuses network, process and file-write events, and a network namespace on Linux when available. | `-I` would drop `PYTHONHASHSEED`; audit hooks are portable and cannot be removed from inside the child, and the static scan of contracts-m0 5.8 already rejects escapes. |
| Sub-plan identity | A dynamic function's sub-plan is traced with the name `<plan>~<node id>` and the governing session, so its node ids depend on the node, not the iteration. | Equal inputs give equal sub-plans and hashes across iterations and runs (cacheable pure sub-plan nodes); instance keys keep iterations apart. |
| Events | Every journal event is published live (not persisted) on the daemon bus; only run created, started, paused, resumed and finished enter the persisted activity feed; the run stream uses journal ids as event ids. | One timeline (the journal) with resumable streams, without doubling every node event into the 90-day activity table. |
| Exit codes | `eks-harness run` exits 0 passed, 1 failed or error or invalid plan, 11 aborted, 12 paused without a terminal. | Reuses the CLI's table (11 is "cancelled") and adds one code for the one new situation. |
| Settings | `engine.*` settings: maxRuns 4, parallelism 4, retries 2, nodeTimeoutSeconds 120, apiTimeoutSeconds 30, pauseTimeoutSeconds 1800, sandboxTimeoutSeconds 30, sandboxMemoryMb 1024, runRetentionDays 30, cacheMaxGb 20, cacheMaxAgeDays 30. | Sized for one hub machine running a few flows and renders at once. |
| Plan diff | `/api/plans` offers build and validate; diff stays with M6 tooling. | decisions-m0 row "plan --diff": a diff that cannot compare node by node yet would be a placeholder. |
| Driver call sites | `DriverPort.call` takes a keyword `site: CallSite(node, instance, attempt)`. | Real ports name evidence and step logs by node instance, and the fake port derives deterministic answers and bytes from the node hash and attempt without a side channel. |
| Debugger journaling | The debugger reports `break.added`, `break.removed` and `break.error` through a `journal` callback given at construction, called outside its lock. | The debugger stays independent of the journal and of the request thread, and breakpoint changes land in the run's one timeline. |
| Live progress | Executor progress is published on the bus as `run.progress`, streamed as id-less `progress` frames and never journaled; at most one call per 0.25 s gets through, and a call with fraction 1.0 always does. | Progress is frequent and worthless after the fact; keeping it out of the journal keeps `Last-Event-ID` resumption exact. |
| Run comparison | Outputs are compared after replacing `Artifact` dumps by their sha256 and the instance's own artifact ids by their position. | Repeated runs ingest identical bytes under new ids; comparing raw ids would report every capture as a divergence. |
| Sandbox guard | The child's guard takes the request limits and is injectable into `sandbox_child.run`. | An audit hook can never be removed from the process that installed it, so in-process tests trace without one while subprocess tests exercise the real guard. |
| Entry files | `PlanBuilder.files` reports every entry file with its entries or its load error; `entries` flattens the loaded ones. | The flows API and the UI list a broken file with its error instead of failing the whole listing. |
| Transition ownership | The run manager journals queued, preparing, running and terminal statuses; the scheduler journals only pauses and resumes. | One writer per transition keeps the order of `run.*` events fixed and lets resource release happen before the terminal status. |
| Backend only when needed | A flow session holds a backend resource only when it names `seed=`, `backend=` or `as_`, or calls an op that uses the backend role; `score.take` needs only a lease. | Requested on 2026-10-14: flows that only drive the UI must not require a backend; a missing backend would otherwise fail admission with no backend policy. |
| Run exit codes | Aborted runs exit 13 and paused runs 12; `RunCreate` gained `repeat_of` so `--repeat` links its runs. | 11 already meant nothing selected or cancelled in the CLI, and the repeat series needs the link the contract describes. |
| CLI follow | `eks-harness run` reads the event stream with reconnection from the last id and looks up op and source per node from the run's plan, then the journal for run-time nodes. | Node events carry only the outcome; the plan and journal give the rest without widening every event. |
