# CLI reference

Generated by `eks-harness docs` from the built-in registry. Do not edit by hand; run `eks-harness docs --out docs/reference` instead.

Every command, subcommand and option of the `eks-harness` CLI, taken from its argparse tree (plugin
commands are left out). `eks-harness help <command> [<subcommand>]` and `--help` print the same help in the
terminal.

## eks-harness

```text
eks-harness: browser and device pools, backends, leases, artifact store, video studio and web UI.

Every command talks to the running daemon over its HTTP API, except setup, auth recover,
daemon install/uninstall/start/stop, update and version, which work on local files.

Output: tables and panels for people; --json (before or after the command) prints plain JSON
on stdout for scripts and agents. In JSON mode a failure is also printed on stdout, as
{"error", "message", "exitCode", ...}, next to the human message on stderr.

No terminal: commands never prompt without one. A missing required value exits with a
message naming the flag to pass, and confirmations need --yes.

Exit codes: 0 ok, 1 error, 2 usage, 3 daemon unreachable, 4 not logged in, 5 forbidden,
6 not found, 7 gone (released sid), 8 conflict, 10 no credentials and no terminal,
11 nothing selected or cancelled, 12 run paused (attach with eks-harness debug),
13 run aborted, 130 interrupted.

Run 'eks-harness help <command> [<subcommand>]' for the help of one command.
```

## eks-harness annotate

Render an annotation spec onto a capture: eks-harness annotate <id> --spec <file>.

Rerender restyles without a device: annotate rerender <id|--session S> [--style Y].
Recapture replays the recipe with a lease: annotate recapture <id|--session S> [--sid SID].
Versions lists and restore rolls back: annotate versions <id>, annotate restore <id> <version>.

| Argument | Help |
| --- | --- |
| `[target]` | artifact id, or one of rerender, recapture, versions, restore. |
| `[extra]` | arguments of the action (artifact id, version number) |
| `--spec SPEC` | spec file (.json, .yaml or .yml) |
| `--style STYLE` | style name overriding the spec style. |
| `--dry-run` | validate and preview crops without storing. |
| `--session SESSION` | session name or slug holding the annotated artifact. |
| `--project PROJECT` | project as owner/name (with --session) |
| `--sid SID` | lease sid for the replay (recapture only) |
| `--json` | print JSON. |

## eks-harness backend

| `--no-wait` | return the lease at once. |

with the CLI's credentials (eks-harness login, or EKS_HARNESS_API_KEY).

Register it with an MCP client, for example:
  claude mcp add eks-harness -- eks-harness mcp

--check verifies the daemon and the credentials and exits; --list-tools prints the tools.

| Argument | Help |
| --- | --- |
| `--check` | check that the daemon is reachable and the key works. |
| `--list-tools` | list the MCP tools and exit. |
| `--json` | print JSON (with --check or --list-tools) |

## eks-harness run

Build the plan of an entry locally, validate it, start it on the hub and follow it until it ends. Exit 0 when it passes, 1 when it fails or the plan is invalid, 13 when it is aborted.

| Argument | Help |
| --- | --- |
| `spec` | file.py or file.py::name. |
| `--set KEY=VALUE` | a parameter of the entry function, parsed into its annotated type (repeatable) |
| `--platform PLATFORM` | the platform of a flow. Choices: `web`, `ios`, `android`. |
| `--backend BACKEND` | backend lease id, backend id or definition for the plan's backends. |
| `--backend-tree BACKEND_TREE` | tree the backend runs from. |
| `--backend-key BACKEND_KEY` | identity of the backend instance instead of the tree. |
| `--project PROJECT` | project owner/name (default: the tree's) |
| `--session SESSION` | session (default: the tree's git branch) |
| `--break SPEC` | pause at a breakpoint: n12, node:n12, op:ui.tap, op:ui.*, label:before-submit, when:EXPR, or several joined with commas (repeatable; implies --debug) |
| `--break-on-error` | pause at a failing node (implies --debug) |
| `--debug` | let breakpoints pause the run and open the debugger. |
| `--repeat N` | run N times and report the nodes whose results differ. Default: `1`. |
| `--cache CACHE` | cache mode for pure nodes. Choices: `use`, `refresh`, `readonly`, `off`. Default: `use`. |
| `--seed SEED_MODE` | restore the seed snapshot unless the backend holds it, restore it always (fresh), build it again (rebuild) or use the backend as it is (skip) Choices: `restore`, `fresh`, `rebuild`, `skip`. Default: `restore`. |
| `--fake FAMILY` | simulate ops of this family (or op) with fake executors; * for every op without a real executor (repeatable) |
| `--no-plugins` | do not import the tree's plugin modules. |
| `--no-wait` | start the run and print its id without following it. |
| `--timeout TIMEOUT` | seconds to follow the run. Default: `3600.0`. |
| `--json` | print the run report as JSON. |
